API tokens

An API token is the one credential your agent needs to deploy, and it's the single human step in the whole flow. You log in once, create a token, and hand it to your agent. Everything after that is automatic.

What it is

A token is a bearer credential tied to your account. It looks like spk_live_1a2b3c…. Your agent sends it to the MCP server on every call, and spawnpoint uses it to figure out which account the deploy belongs to.

Why it exists

spawnpoint's whole promise is "you do one thing: log in." The token is that one thing. Instead of wiring up cloud accounts, IAM, and deploy keys, you hand your agent a single token and it can ship on your behalf, nothing more to configure.

Create one

  1. Sign in to your console.
  2. Open the API tokens panel and click Create token.
  3. Copy the spk_live_… value immediately: it's shown once and never again.

Use it

Give it to your agent as the MCP bearer token:

Authorization: Bearer spk_live_your_token

Or in an MCP client config:

"headers": { "Authorization": "Bearer spk_live_your_token" }

How we keep it safe

  • Hashed at rest. We store only a hash of your token, the raw value is shown once at creation and we can't recover it.
  • Revoke anytime. Revoke a token from the console and it stops working instantly.
  • Scoped to you. A token only ever touches its own account's projects.

Good practice

  • Don't commit tokens to a repo or paste them in chats.
  • Use a separate token per agent or environment, so you can revoke one without touching the others.
  • Rotate periodically, create a new one, swap it in, revoke the old.
Lost a token? You can't view it again, but you can revoke it and create a fresh one in seconds.

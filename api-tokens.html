API tokens

A long-lived bearer credential for clients that can't sign in through a browser. Most people never need one: Claude Code and other OAuth-capable agents connect without any key to copy.

Try OAuth first. Install the plugin and run /mcp → spawnpoint → Authenticate; see Getting started. Use a token only when the client is a script, a CI job, or something else that can't do a browser sign-in.

What it is

A token is a bearer credential tied to your account. It looks like spk_live_1a2b3c…. Your client sends it to the MCP server on every call, and spawnpoint uses it to figure out which account the deploy belongs to. The endpoint accepts it in place of an OAuth access token.

When to use one

OAuth is the default because you never paste a secret anywhere: you approve once in the browser, and your agent stores and refreshes the credentials itself. Use a token where OAuth does not work: a shell script, a cron job, a CI pipeline, or an MCP client with no OAuth support.

Create one

  1. Sign in to your console.
  2. Open the API tokens panel and click Create token.
  3. Copy the spk_live_… value immediately: it is shown only once.

Use it

Send it as the bearer token on the MCP endpoint:

Authorization: Bearer spk_live_your_token

How we keep it safe

  • Hashed at rest. We store only a hash of your token. The full value is shown once, when you create it, and we can't recover it.
  • Revoke anytime. Revoke a token from the console and it stops working instantly.
  • Scoped to you. A token can reach only its own account's projects.

Good practice

  • Don't commit tokens to a repo or paste them in chats.
  • Use a separate token per agent or environment, so you can revoke one without touching the others.
  • Replace tokens from time to time: create a new one, switch your client to it, then revoke the old one.
If you lose a token, you can't view it again. Revoke it in the console and create a new one.
